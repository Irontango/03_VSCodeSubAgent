# ADR-0002: 게임 규칙(도메인)과 렌더링·입력·오디오·저장의 분리

날짜: 2026-09-16
상태: 채택

## 맥락

프로토타입은 단일 스크립트에 상태, 업데이트, 그리기, 입력, 사운드, localStorage 접근이 섞여 있었다.
이 구조에서는 규칙을 검증하려면 브라우저가 필요하고, 밸런스 수치 변경이 렌더링 코드에 영향을 준다.
NFR-5(규칙 로직의 Node 실행 가능)와 NFR-6(결정성)을 만족해야 한다.

## 결정

다음 계층으로 나눈다. 화살표는 허용된 의존 방향이다.

```
main.ts ──► input.ts ──┐
        ──► renderer.ts├──► game.ts ──► entities.ts ──► config.ts
        ──► audio.ts   │           └──► rng.ts
        ──► storage.ts ┘
```

- `game.ts`(도메인)는 DOM, Canvas, Audio, localStorage를 import하지 않는다. 외부 효과(효과음 재생, 점수 저장)는 이벤트 목록으로 노출하고 `main.ts`가 어댑터로 전달한다.
- 난수는 `Rng` 인터페이스로 주입한다. 테스트는 시드 고정 구현을, 런타임은 시드 기반 구현을 사용한다.
- 모든 수치 상수는 `config.ts`에 둔다.

## 결과

- 규칙 테스트가 jsdom 없이 Vitest에서 밀리초 단위로 실행된다.
- 렌더러는 `GameState`를 읽기만 하며, 상태를 바꾸지 않는다.
- 어댑터 계층이 하나 늘어나 파일 수가 증가한다. 게임 크기에 비해 과하지 않다고 판단했다.
