# 갤러그 웹 게임 요구사항 명세

버전: 1.0 (2026-09-16)
상태: 확정

이 문서는 갤러그 스타일 웹 슈팅 게임의 기능·비기능 요구사항과 인수 기준을 정의한다.
모든 요구사항은 식별자를 가지며, 테스트 코드와 PR 설명에서 이 식별자로 참조한다.

## 1. 범위

### 1.1 포함

- 단일 플레이어 고정 화면 슈팅 게임
- 키보드 및 터치 조작
- 로컬 최고 점수 저장

### 1.2 제외 (이번 버전에서 다루지 않음)

- 온라인 랭킹, 계정, 서버 통신
- 원작의 보스 포획(트랙터 빔) 및 듀얼 파이터
- 챌린징 스테이지, 보너스 아이템
- 게임패드 입력
- 다국어 지원 (UI 텍스트는 한국어와 영어 혼용 고정)

## 2. 기능 요구사항 (FR)

### 2.1 플레이어

| ID | 요구사항 |
|---|---|
| FR-P1 | 플레이어 기체는 화면 하단에서 좌우로만 이동한다. 화면 경계를 벗어나지 않는다. |
| FR-P2 | 플레이어는 위쪽으로 탄을 발사한다. 화면에 동시에 존재하는 플레이어 탄은 최대 3발이다. |
| FR-P3 | 발사 후 재발사까지 최소 쿨다운 시간이 있다. |
| FR-P4 | 플레이어는 목숨 3개로 시작한다. 피격 시 목숨이 1 감소하고, 일정 시간 후 화면 중앙에서 재출현한다. |
| FR-P5 | 재출현 직후 일정 시간 동안 무적이며, 무적 상태는 깜빡임으로 표시된다. |
| FR-P6 | 목숨이 0인 상태에서 피격되면 게임 오버가 된다. |

### 2.2 적

| ID | 요구사항 |
|---|---|
| FR-E1 | 적은 보스, 나비, 벌 세 종류다. 종류별 체력과 점수는 [부록 A]를 따른다. |
| FR-E2 | 웨이브 시작 시 적은 화면 밖에서 순차적으로 진입하여 정해진 대형 위치로 이동한다. |
| FR-E3 | 대형에 합류한 적은 대형 전체와 함께 좌우로 완만하게 흔들린다. |
| FR-E4 | 대형의 적은 무작위로 급강하를 시작한다. 급강하 경로는 곡선이며 플레이어 근처를 지나 화면 아래로 빠진다. |
| FR-E5 | 급강하 중인 적은 플레이어를 향해 조준탄을 발사한다. |
| FR-E6 | 화면 아래로 빠진 적은 화면 위에서 다시 나타나 대형 위치로 복귀한다. |
| FR-E7 | 대형의 적은 낮은 확률로 아래 방향 직선탄을 발사한다. |
| FR-E8 | 급강하 중인 적과 플레이어가 충돌하면 적은 파괴되고 플레이어는 피격된다. |

### 2.3 점수와 진행

| ID | 요구사항 |
|---|---|
| FR-S1 | 적을 파괴하면 종류별 점수를 얻는다. 급강하 중인 적은 대형 점수보다 높은 급강하 점수를 준다. |
| FR-S2 | 화면의 모든 적이 파괴되면 웨이브 클리어 연출 후 다음 웨이브가 시작된다. |
| FR-S3 | 웨이브가 올라갈수록 적의 이동 속도, 급강하 빈도, 사격 빈도, 탄속이 증가한다. |
| FR-S4 | 최고 점수는 브라우저 로컬 저장소에 보존되며 다음 실행 시 표시된다. |
| FR-S5 | 게임 오버 시 현재 점수가 최고 점수 이상이면 갱신하고 "NEW HI-SCORE"를 표시한다. |

### 2.4 화면과 흐름

| ID | 요구사항 |
|---|---|
| FR-U1 | 게임은 타이틀, 플레이, 일시정지, 웨이브 클리어, 게임 오버 다섯 화면 상태를 가진다. 전이는 `docs/state-machine.md`를 따른다. |
| FR-U2 | 타이틀 화면은 게임 이름, 시작 방법, 최고 점수, 적 종류별 점수표를 표시한다. |
| FR-U3 | 플레이 중 HUD는 현재 점수, 최고 점수, 웨이브 번호, 남은 목숨을 표시한다. |
| FR-U4 | 일시정지 중에는 게임 로직이 멈추고 "PAUSED"가 표시된다. 창이 포커스를 잃으면 자동으로 일시정지된다. |
| FR-U5 | 적 파괴, 플레이어 피격 시 파티클 폭발 효과를 표시한다. |
| FR-U6 | 배경에는 아래로 흐르는 별이 표시된다. |

### 2.5 입력

| ID | 요구사항 |
|---|---|
| FR-I1 | 키보드: ← → 또는 A/D 이동, SPACE 또는 Z 발사, ENTER 시작·재시작, P 또는 ESC 일시정지 토글. |
| FR-I2 | 터치 기기에서는 화면 하단에 좌·우·발사 버튼을 표시한다. |
| FR-I3 | 타이틀 또는 게임 오버 화면에서 캔버스를 터치·클릭하면 게임을 시작한다. |

### 2.6 사운드

| ID | 요구사항 |
|---|---|
| FR-A1 | 발사, 적 피격, 적 파괴, 플레이어 피격, 웨이브 클리어 시 효과음을 재생한다. |
| FR-A2 | 효과음은 외부 파일 없이 Web Audio API로 합성한다. |
| FR-A3 | 오디오를 지원하지 않는 환경에서도 게임은 정상 동작한다. |

## 3. 비기능 요구사항 (NFR)

| ID | 요구사항 | 검증 방법 |
|---|---|---|
| NFR-1 | 런타임 외부 의존성이 없다. 배포 산출물은 단일 HTML 파일이다. | 빌드 산출물 검사 (`dist/index.html` 하나, 외부 URL 참조 없음) |
| NFR-2 | 데스크톱 브라우저(Chrome, Edge, Firefox, Safari 최신 2개 버전)에서 동작한다. | E2E 테스트 (Chromium), 수동 확인 |
| NFR-3 | 모바일 브라우저에서 캔버스가 화면 폭에 맞게 축소된다. | E2E 뷰포트 테스트 |
| NFR-4 | 일반적인 데스크톱에서 60fps를 유지한다. 프레임 간격이 커져도 로직은 프레임 독립적이다(시간 기반 업데이트). | 단위 테스트 (dt 분할 불변성), 디버그 오버레이 fps |
| NFR-5 | 게임 규칙 로직은 DOM·Canvas·Audio에 의존하지 않고 Node 환경에서 실행·테스트 가능하다. | 단위 테스트가 jsdom 없이 통과 |
| NFR-6 | 동일한 난수 시드와 입력 시퀀스는 동일한 결과를 만든다(결정성). | 통합 테스트 |
| NFR-7 | 밸런스 수치(점수, 속도, 빈도)는 코드 로직과 분리된 설정 파일에 있다. | 코드 리뷰 체크리스트 |

## 4. 인수 기준 (AC)

각 항목은 자동 테스트로 검증한다. 괄호는 대응 테스트 파일이다.

| ID | 기준 | 관련 FR |
|---|---|---|
| AC-1 | 새 게임 시작 시 점수 0, 목숨 3, 웨이브 1, 적 40마리가 생성된다. (`game.test.ts`) | FR-P4, FR-E1 |
| AC-2 | 플레이어 탄은 동시에 3발을 넘지 않는다. (`game.test.ts`) | FR-P2 |
| AC-3 | 플레이어는 화면 밖으로 나가지 않는다. (`game.test.ts`) | FR-P1 |
| AC-4 | 벌을 대형에서 파괴하면 50점, 급강하 중 파괴하면 100점을 얻는다. (`scoring.test.ts`) | FR-S1 |
| AC-5 | 보스는 두 번 맞아야 파괴된다. (`game.test.ts`) | FR-E1 |
| AC-6 | 충분한 시간이 지나면 모든 적이 대형 위치에 도달한다. (`simulation.test.ts`) | FR-E2 |
| AC-7 | 모든 적을 제거하면 WAVE_CLEAR 상태가 되고, 연출 시간 후 웨이브 2가 시작된다. (`game.test.ts`) | FR-S2 |
| AC-8 | 목숨 0에서 피격되면 GAMEOVER가 되고 최고 점수가 갱신된다. (`game.test.ts`) | FR-P6, FR-S5 |
| AC-9 | 같은 시드로 두 번 시뮬레이션하면 상태가 동일하다. (`simulation.test.ts`) | NFR-6 |
| AC-10 | 타이틀 → ENTER → 플레이 → P → 일시정지 → P → 플레이 흐름이 브라우저에서 동작한다. (`e2e/game.spec.ts`) | FR-U1, FR-I1 |
| AC-11 | 빌드 산출물은 `dist/index.html` 하나이며 외부 스크립트를 참조하지 않는다. (`e2e/build.spec.ts`) | NFR-1 |

## 부록 A. 적 종류별 수치

| 종류 | 색 | 체력 | 대형 점수 | 급강하 점수 | 웨이브당 수 |
|---|---|---|---|---|---|
| 보스 | 초록 | 2 | 150 | 400 | 4 |
| 나비 | 빨강 | 1 | 80 | 160 | 16 |
| 벌 | 파랑 | 1 | 50 | 100 | 20 |

실제 값은 `src/config.ts`가 단일 진실 공급원이며, 이 표와 불일치하면 설정 파일을 기준으로 문서를 갱신한다.
