# 코드 리뷰 체크리스트

PR 리뷰 시 아래 항목을 확인한다. 하나라도 해당하지 않으면 이유를 코멘트로 남긴다.

## 요구사항 추적

- [ ] 변경이 `docs/requirements.md`의 어느 FR/NFR/AC에 대응하는지 PR 설명에 적혀 있다.
- [ ] 새 동작이나 규칙 변경이면 요구사항 문서가 함께 수정됐다.
- [ ] 화면·적·플레이어 상태 전이를 바꿨다면 `docs/state-machine.md`가 함께 수정됐다.
- [ ] 구조적 결정(라이브러리 도입, 계층 변경)은 ADR로 남겼다.

## 설계 규칙 (ADR-0002)

- [ ] `src/game.ts`, `entities.ts`, `config.ts`, `rng.ts`, `types.ts`는 DOM·Canvas·Audio·localStorage를 참조하지 않는다.
- [ ] 상태 전이는 `Game.dispatch()`와 `Game.update()` 안에서만 일어난다.
- [ ] 렌더러는 `GameState`를 읽기만 한다.
- [ ] 부수 효과(소리, 저장)는 `Effect`로 반환하고 `main.ts`가 처리한다.
- [ ] 난수는 주입된 `Rng`만 사용한다. `Math.random` 직접 호출은 어댑터 계층에만 있다.

## 수치와 설정 (NFR-7)

- [ ] 새 매직 넘버가 로직 코드에 들어가지 않았다. 밸런스·레이아웃 값은 `src/config.ts`에 있다.
- [ ] 부록 A(적 수치)를 바꿨다면 문서 표도 갱신됐다.

## 테스트

- [ ] 새 규칙에는 단위 테스트가, 버그 수정에는 회귀 테스트가 있다.
- [ ] 테스트 이름에 FR/AC 식별자가 붙어 있다.
- [ ] 결정성 테스트(AC-9)가 여전히 통과한다. 시드 소비 순서를 바꿨다면 의도된 변경인지 확인한다.
- [ ] `npm run check`가 통과한다.

## 코드 품질

- [ ] `any`, non-null 단언(`!`)을 쓰지 않았다. 상태에 따라 있거나 없는 값은 유니온 타입으로 표현했다.
- [ ] 프레임 의존 로직이 없다. 이동·타이머는 모두 `dt` 기반이다.
- [ ] 배열을 매 프레임 새로 만들거나 필터하는 코드가 눈에 띄게 늘지 않았다.

## 사용자 영향

- [ ] 조작법이 바뀌었으면 타이틀 화면 안내와 README를 갱신했다.
- [ ] 모바일(터치)에서도 동작한다.
