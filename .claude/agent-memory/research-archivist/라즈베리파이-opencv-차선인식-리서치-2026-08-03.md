**주제**: 라즈베리파이 기반 OpenCV 차선 인식 최신 기법 (2026-08-03 격주 리서치)
**보고서**: outputs/2026-08-03-라즈베리파이-OpenCV-차선인식-최신기법.md

**이전 리서치와의 관계:** [[rc카-자율주행-리서치-2026-07-19]]에서 Donkeycar를 자율주행 표준 프레임워크로 확인했고, [[초음파-센서-장애물회피-리서치-2026-07-20]]에서 장애물 회피를 다뤘음. 이번 리서치는 RC카의 "시각 인식(차선 인식)" 축을 전통 CV 기법과 경량 딥러닝 기법 양쪽으로 조사함.

핵심 발견:
1. 전통 CV 기법(Canny+Hough+슬라이딩윈도우)이 여전히 저사양 라즈베리파이에서 안정적인 실무 선택지. GitHub 오픈소스 사례 다수(uvbakutan, salimandre, emirelesg, jerinpeter 등) 확인. 다만 대부분 **Pi 3/3B+ 세대 기준**이며 **Pi5/Bookworm 호환성은 미검증** — 이 RC카 프로젝트가 Pi5를 채택할 경우([[rc카-자율주행-리서치-2026-07-19]] 참고) 이 코드베이스들의 재검증이 필요함.
2. **FPS 수치 상충 발견 — 인용 주의**: zbotic.in 블로그의 "Pi5 640×480 30+fps" 주장은 벤치마크 근거가 없는 저신뢰 SEO 마케팅 콘텐츠(Scam Detector 사이트 신뢰도 13.1점, 매우 낮음)로 판정됨 — **향후 인용 금지**. 대신 GitHub uvbakutan 실측치 "7fps"(조건 불명확하나 실측 기반)를 참고할 것.
3. **CircuitDigest 발행일 오탐 — 방법론 3번째 재확인**: "Autonomous Lane Detection Car Using Raspberry Pi and OpenCV" Part1/2 글이 검색엔진에는 2025~2026년으로 노출되지만 실제로는 **2021-11-18** 콘텐츠로 추정됨(Tumblr 재게시 URL 패턴이 근거; Wayback 직접 대조는 접근 차단으로 미완). 상세는 [[리서치-발행일-검증-방법론]] 참고.
4. 경량 딥러닝 기반 차선검출은 라즈베리파이 실전 검증 사례가 아직 부족함. DeepUNet24가 CULane 259FPS를 주장하나 이는 **고성능 GPU 기준**으로 추정되며, 저자군 스스로 임베디드(Jetson/Pi) 배포의 어려움을 인정(Jetson 계열도 21~32FPS 수준). 라즈베리파이 실측치는 발견되지 않음.
5. **신뢰할 수 있는 경량 딥러닝 참고사례**: Springer "Embedded Intelligent ADAS Car Prototype Using Raspberry Pi and YOLOv12n"(D.G. Narayan 등, KLE Technological University 소속 확인됨, 레드플래그 없음). Pi3 단독추론 약 6fps이나, 초음파+차선검출+GPIO 통합 전체 파이프라인은 약 1fps로 급감. **다중 센서/모델 통합 시 Pi3 수준에서는 실시간성 확보가 어렵다는 실증적 시사점** — 향후 이 RC카 프로젝트에서 초음파([[초음파-센서-장애물회피-리서치-2026-07-20]])와 차선인식을 동시에 파이프라인에 태울 때 반드시 이 성능 저하를 감안해 설계할 것 (Pi5 채택 여부, 파이프라인 단순화 여부 등).
6. Donkeycar가 딥러닝 오토파일럿 외에도 **"컴퓨터비전 오토파일럿"**(색공간변환+엣지검출로 트랙 중앙 라인 추적 + PID)을 공식 지원함을 확인 — [[rc카-자율주행-리서치-2026-07-19]]에서 확인한 Donkeycar 표준 채택과 시너지 가능. 후속 리서치에서 Donkeycar CV 오토파일럿의 실전 적용 사례를 더 파볼 가치 있음 (미해결 공백으로 표시).
7. **arXiv 2603.13907 "LineMaster Pro" 재검증 — 의심 판정 재확인 및 강화**: [[arxiv-논문공장-탐지-방법론]]에서 정리된 저자 소속(간호학과/사회복지학과) 불일치가 이번 세션에서 독립적으로 재확인됨. 추가로 이 논문의 실제 주제가 "OpenCV 카메라 차선인식"이 아니라 **"적외선 센서 라인트레이서"**임이 확인됨 — 향후 "차선인식"/"라인 추종" 관련 검색에서 재등장할 가능성이 높으므로 계속 경계 필요. 인용 금지 유지.
8. **방법론 관찰(신규): WebFetch 403 다발**: 이번 세션에서 WebFetch가 arxiv.org, nature.com, researchgate.net, dl.acm.org, pmc.ncbi.nlm.nih.gov, mdpi.com, web.archive.org, tumblr.com, circuitdigest.com, zbotic.in, hackster.io, docs.donkeycar.com 등 다수 학술/블로그 도메인에서 반복적으로 HTTP 403을 반환함 — WebSearch 간접 확인(스니펫/캐시)에 크게 의존해야 했음. 세션 환경 특성일 가능성도 있으므로 향후 리서치에서 재현되는지 계속 관찰 필요.

**Why:** RC카 프로젝트의 시각 인식(차선 인식) 구현 방식을 결정하기 위한 격주 정기 리서치. 전통 CV와 경량 딥러닝 중 어느 쪽이 저사양 하드웨어에 적합한지 비교.
**How to apply:** 차선 인식 구현 논의 시 (a) Pi3/3B+에서는 전통 CV(Canny+Hough+슬라이딩윈도우) 우선 고려, Pi5 채택 시에는 기존 GitHub 코드베이스 재검증 필요, (b) zbotic.in의 "30+fps" 수치는 인용/설계 근거로 사용 금지, uvbakutan의 "7fps"를 참고 기준으로 사용, (c) 다중 기능(초음파+차선인식) 동시 구동 설계 시 YOLOv12n 사례(통합 시 ~1fps)를 참고해 실시간성 저하를 사전에 고지, (d) CircuitDigest 글의 실제 연식(2021)을 최신 기법 근거로 사용하지 말 것, (e) arXiv 2603.13907은 어떤 맥락(라인트레이서/차선인식)으로 재등장하든 인용 금지 유지.
