**주제**: RC카 PWM/GPIO 모터 제어 오픈소스 프로젝트 동향 (2026-08-17 리서치)
**보고서**: outputs/2026-08-17-RC카-PWM-GPIO-모터제어-오픈소스-동향.md
**이전 리서치와의 관계**: [[rc카-자율주행-리서치-2026-07-19]]가 3절에서 L298N 튜토리얼 위주로 얕게 다룬 모터 제어 영역을 특화·심화한 후속 리서치.

핵심 발견:

1. **★ Pi5 GPIO 이슈 후속 결말 확정 — 향후 리서치에서 재확인 불필요.** gpiozero Issue #1166(Pi5 lgpio 핀 팩토리가 gpiochip 4→0 변경으로 깨진 버그, 2024-08-21 제보)이 **2026-07-25에 종료(closed)**되고, 같은 날 배포된 **gpiozero 2.0.1.post1**(이후 post2 yank를 거쳐 **post3, 2026-07-27**) 공식 changelog에 "Fixed LGPIOFactory defaulting to the wrong GPIO chip on the Raspberry Pi 5... (#1166)"라고 명시적으로 연결된 것을 원문에서 직접 확인함. 즉 **2024년 8월에 보고된 버그가 약 2년 뒤인 2026년 7월에야 pip 정식 배포판에서 수정**됨. "Pi5 GPIO 대응이 신속히 성숙했다"는 통념과 배치되는 결과.

2. **GPIO 라이브러리 생태계 계층 구조 (검증됨).**
   - gpiozero: 상위 레이어, 가장 활발 (최신 2.0.1.post3, 2026-07-27)
   - rpi-lgpio(waveform80): 하위 호환 shim, 개발 정체(최신 릴리스·커밋 모두 2024-05-11 이후 없음, 약 2년 정체) — 그럼에도 RpiMotorLib 등 상위 라이브러리가 의존성으로 채택 중
   - lgpio(joan2937/lg): PyPI 최신 0.2.2.0 (2024-03-29)
   - pigpio(joan2937): 사실상 폐기 수순. 최신 태그 v79(2021-03-02), 5년+ 무갱신, Pi5 구조적 미지원(RP1 재설계로 하드코딩 차단, Issue #589)

3. **모터 드라이버 라이브러리 중 가장 활발한 프로젝트: RpiMotorLib**(gavinlyonsrepo). 스타 337, GPLv3(단, GitHub API license 필드는 "Other"로 오분류되며 LICENSE 원문 대조로 GPLv3 확인 — 아래 방법론 메모 참고). v4.0.0부터 rpi-lgpio를 채택해 Pi5 포함 전 모델 호환. 2026-05-11까지 커밋 지속 — 조사 대상 GPIO/모터 라이브러리 4개 중 유일하게 2026년 활동이 확인됨.

4. **미확인으로 남아 향후 리서치 후보**: TB6612FNG 소형 프로젝트(nick-hunter 등)의 활동 지표, pigpio-rp5(rgpio/kshetline, Pi5 대응 실험적 포크)의 정확한 저장소·성숙도(정확한 URL조차 미확인), PID 제어 루프(2026-07-19 문서에서도 공백, 아직 미착수).

**Why:** RC카 프로젝트의 모터 제어 계층(PWM/GPIO)이 Pi5 전환과 맞물려 반복적으로 질문될 가능성이 높은 영역이며, 특히 Pi5 GPIO 버그의 "해결 여부"는 매 리서치마다 재조사하기보다 이번에 확정된 사실을 재사용하는 것이 효율적임.
**How to apply:** (1) Pi5 GPIO 관련 질문이 다시 나오면 이 메모의 #1(Issue #1166 해결)을 바로 인용하고 재조사하지 말 것 — gpiozero>=2.0.1.post3 사용을 전제로 안내. (2) 모터 드라이버 라이브러리 추천 시 RpiMotorLib을 1순위 후보로 우선 검토. (3) pigpio는 신규 프로젝트에 권장하지 말 것(Pi5 미지원 구조적). (4) PID 제어 루프, pigpio-rp5 성숙도는 여전히 리서치 공백이므로 관련 요청 시 신규 조사 필요.
