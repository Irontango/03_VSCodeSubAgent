1. **Nerdy-Things/raspberry-pi-5-pwm-motor-control 비활성 지속 확정.** 2024-05-09 마지막 커밋 이후 이번 회차(2026-10-26)까지도 신규 커밋 전혀 없음. 라이선스 여전히 미지정, star 1/fork 1로 변동 없음. → 1회차에서 관찰한 "정지 상태"가 약 2개월 추가 경과 후에도 그대로 지속됨을 확정(활성 레퍼런스로서의 가치는 계속 낮게 평가).

2. **★신규 핵심 발견: IliaLarchenko/lerobot_phone_teleop.** Hugging Face LeRobot 생태계의 LeKiwi 로봇을 Flutter(Android) 앱 + WebSocket으로 원격 조종. Apache License 2.0 — Nerdy-Things(라이선스 미지정)보다 재사용성이 명확히 우수. 최종 커밋 2025-06-20으로 Nerdy-Things보다 훨씬 최근.
   - **단, 저장소 자체 README에는 "Raspberry Pi" 직접 언급이 없음.** 라즈베리파이는 LeKiwi 상위 생태계 문서(Seeed Studio wiki 등)에서 "통상 권장 호스트"로만 간접 언급되며, "5V 구동+USB 포트가 충분하면 다른 PC로도 대체 가능"하다고 되어 있어 **라즈베리파이 전용 구성은 아님**. 판정은 "부분 확인"에 그침(4조건: Flutter/WebSocket/라이선스/최종커밋일은 확인됨, 라즈베리파이 전용성은 미확인).
   - **방법론 패턴(신규 일반화 후보)**: 1차 저장소 README에는 특정 하드웨어 언급이 없고, 그 하드웨어가 "상위 생태계 문서"에서만 간접적으로(그것도 대체 가능한 옵션으로) 언급되는 경우가 있음 — "저장소 자체 문서 vs 생태계 문서"의 소스 층위를 구분해서 판정 신뢰도를 표기할 것. 다음 회차 이후 유사 사례 재발 시 이 메모를 참조해 패턴을 공식화할 것.

3. **버전 정보 확정 (1차 소스 재확인, 상충 해소):**
   - `web_socket_channel` 최신 **3.0.3**, 게시일 2025-04-17 — pub.dev API로 날짜까지 완전 확인(1회차 수치와 동일, 변동 없음).
   - Python `websockets` 최신 **17.3**(2026-10-19 릴리즈), Python 3.11~3.15 지원 — 신규 확인.
   - Flutter stable **3.47**(2026-08-12 출시, Dart 3.13.0 동반) — 검색 스니펫 간 3.44(outdated)/3.47/3.50(미출시, 2026-11 예정) 상충을 flutter.dev 공식 블로그·docs.flutter.dev 교차확인으로 해소. **다음 회차(격주) 리서치 시점에는 Flutter 버전이 다시 바뀌어 있을 가능성이 높으므로, "3.47이 2026-10-26 기준 최신"이라는 시점 전제를 반드시 재확인할 것** — 과거 [[리서치-발행일-검증-방법론]]의 "오래된 콘텐츠 최신 오인" 함정과 유사한 구조(빠르게 변하는 버전 정보는 시점 명시 없이 인용하면 바로 stale화됨).

4. **이월 과제 2회차 연속 공백 확정.** Hackster.io, 라즈베리파이 공식 포럼에서 Flutter+WebSocket+RPi+모터제어 사례를 재조사했으나 이번에도 발견 못함(1회차 2026-08-31에 이어 **2회차 연속 공백**). GitHub topic 검색 등 보조 검색 전략도 이번 회차에 시도했으나 수행 실패(환경/도구 제약으로 추정, 구체 원인 미규명).
   - **권고**: 다음 회차부터 이 이월 과제의 우선순위를 낮추거나([[라즈베리파이-opencv-차선인식-리서치-2026-09-28]]의 "Donkeycar 공백 → forum 미색인 구조적 원인 진단" 사례처럼), 플랫폼 자체를 교체하는 전략 전환을 검토할 것.

5. **1차 도메인 DNS 실패(ENOTFOUND) 패턴 — 새 도메인 군에서 재현.** `huggingface.co`, `flutter.dev` 계열, `wiki.seeedstudio.com` 등에 대한 WebFetch 직접 접근이 ENOTFOUND(DNS 해석 실패)로 막혀 WebSearch 스니펫 기반 대체 검증으로 전환함. 이는 [[webfetch-403-접근제한-관찰]]에서 2026-10-12에 처음 기록된 "DNS 해석 실패(ENOTFOUND)" 실패 유형(그때는 `gpiozero.readthedocs.io`)과 **동일한 실패 유형이 다른 도메인 군에서 재현**된 것 — 403/EGRESS_BLOCKED와는 구분되는 별개 원인(DNS)임을 재확인. webfetch-403 메모에 재확인 기록 추가함(아래 Related 참고).
