라즈베리파이/RC카 자율주행 분야 웹 리서치(2026-07-19, [[rc카-자율주행-리서치-2026-07-19]]) 중 관찰된 방법론적 이슈:

1. 검색엔진 상위에 노출되지만 실제 발행일은 오래된(예: 2017년경) 콘텐츠가 다수 존재함 (diyrobocars.com, Raspberry Pi Magazine 기사 등). "최신 동향"을 다루는 리서치에서는 반드시 페이지 내에서 실제 발행/수정일을 직접 확인해야 함.
2. IEEE 등 학술 논문에 등장하는 구체적 수치(예: 인식 정확도 86%/90%)는 원문이 유료 접근 제한(paywall)에 걸려 있어 검색엔진 색인 초록만으로는 완전한 교차검증이 어려운 경우가 있음.

**Why:** web-researcher/source-verifier 파이프라인이 "최신 동향"을 조사할 때 오래된 콘텐츠를 최신으로 오인해 보고할 위험이 확인됨. 학술 수치는 초록만으로 검증했다고 오인하면 신뢰도를 과장하게 됨.
**How to apply:** web-researcher는 소스 수집 시 각 페이지의 실제 발행/수정일을 명시적으로 확인·기록. source-verifier는 학술 논문 수치를 교차검증할 때 원문 접근이 불가능한 경우 "미검증(접근 제한)"으로 명확히 구분 표기하도록 안내. RC카뿐 아니라 다른 임베디드/하드웨어 분야 리서치에도 동일하게 적용 가능한 일반 교훈.

**재확인 (2026-07-20):** 초음파 센서 장애물 회피 리서치([[초음파-센서-장애물회피-리서치-2026-07-20]])에서도 동일 패턴 재관찰됨 — automaticaddison.com 등 커뮤니티/블로그 사이트가 검색 결과에서 최신처럼 노출되었으나 실제 발행일은 2019년이었음. 이 방법론이 특정 사이트 한정 문제가 아니라 반복적으로 나타나는 일반 패턴임이 재입증됨.

**재확인 (2026-08-03, 3번째): CircuitDigest 사례.** 라즈베리파이 OpenCV 차선 인식 리서치([[라즈베리파이-opencv-차선인식-리서치-2026-08-03]])에서 CircuitDigest의 "Autonomous Lane Detection Car Using Raspberry Pi and OpenCV" (Part1/2) 글이 검색엔진에는 2025~2026년 최신 콘텐츠로 노출되었으나, 실제로는 2021-11-18 콘텐츠로 추정됨(Tumblr 재게시 URL 패턴이 근거; Wayback Machine 직접 대조는 접근 차단(HTTP 403, [[webfetch-403-접근제한-관찰]] 참고)으로 완결하지 못함). diyrobocars.com(2026-07-19) → automaticaddison.com(2026-07-20) → circuitdigest.com(2026-08-03)으로 이어지며, 서로 다른 3개 세션·3개 사이트에서 동일 패턴이 반복 확인됨. 이는 특정 사이트의 문제가 아니라 "RC카/임베디드 블로그·튜토리얼 콘텐츠 전반"에 구조적으로 나타나는 SEO/재게시 관행으로 판단하는 것이 타당함 — 향후 리서치에서는 이 분야 콘텐츠의 발행일을 기본적으로 의심하고 검증하는 것을 표준 절차로 삼을 것.

**재확인 (2026-08-17, 4번째, 변종 패턴): PCA9685 연도 오기 사례.** RC카 PWM/GPIO 모터 제어 리서치([[pwm-gpio-모터제어-리서치-2026-08-17]])에서는 "오래된 콘텐츠를 최신으로 오인"이 아니라, web-researcher가 Adafruit_CircuitPython_PCA9685 최신 릴리스일을 "2024-04-23"으로 잘못 보고했으나 source-verifier가 GitHub Releases/Tags API·PyPI 3곳 교차확인으로 실제로는 **2026-04-23**임을 확인·정정한 사례. 이전 3건이 "사이트가 오래된 콘텐츠를 최신처럼 노출"하는 패턴이었다면, 이번은 "연도 숫자 자체의 단순 착오(2024↔2026)"라는 새로운 변종. 발행일/릴리스일 검증은 사이트의 표시 문제뿐 아니라 수집·기록 과정의 단순 오기 가능성도 함께 의심해야 함을 시사. 상세는 [[소스검증-함정-2026-08-17]] 참고.

**재확인 (2026-09-28, 5번째, 신규 변종): GitHub 자동봇 커밋 사례.** 라즈베리파이 OpenCV 차선 인식 4회차 격주 후속 리서치([[라즈베리파이-opencv-차선인식-리서치-2026-09-28]])에서 Ali-Kalsekar/Lane-Detection-and-Driver-Assistance-System 저장소가 "v1.0.0(2024)" 자체 표기임에도 GitHub 메타데이터상 2026-09-27 업데이트로 노출되어 "활발한 신규 프로젝트"처럼 보이는 사례가 확인됨. 실제 커밋 내역을 확인한 결과 대부분이 "Auto-update README login stamp"라는 **자동화 봇 커밋**(잔디 유지용으로 추정)이었고, 실질적 기능 수정은 1건뿐이었음. 이전 4건이 콘텐츠의 표시 발행일이나 릴리스일 숫자 자체의 문제였다면, 이번은 "**저장소 활동 지표(최근 업데이트일) 자체가 자동봇 커밋으로 부풀려질 수 있다**"는 새로운 유형 — GitHub 저장소를 "최근 업데이트일"만으로 활발하다고 판단하지 말고 커밋 메시지 내용까지 확인하는 것을 표준 절차로 추가할 것.
