## 핵심 요약 (3줄)

1. **이월된 4대 공백 중 완전히 해소된 항목은 없다.** Pi5/Bookworm 호환성은 vlmarkov/self-driving-car가 Pi5 자체는 지원하나 OS가 Ubuntu 24.04라 "순수 Bookworm" 공백은 여전하고, Donkeycar 실전 CV 사례는 포럼 접근 차단이 지속되어 미해소다(단 GitHub 공식 이슈트래커 직접 확인으로 "2026년 신규 활동 없음"은 소극적으로 확인됨). nima-salamat 저장소의 실측 fps/정확도도 여전히 공개되지 않았다.
2. **2026년 하반기 신규 학술 자료 5건(MDPI BLSF, arXiv 2601.01696/2604.02188/2604.22872 등)을 신규 확보**했으나, arXiv/MDPI 원문이 전부 WebFetch 차단(ENOTFOUND)되어 **2차 미러·검색 스니펫 기반 "부분확인" 수준에 머문다.** 특히 "2GHz ARM CPU"는 특정 라즈베리파이 모델과 정확히 매칭되지 않으며(반증에 가까움), "저전력 임베디드=라즈베리파이"라는 일반화도 다수 소스에서 Pi 명시 언급이 전혀 없어 미확인/반증에 가깝다.
3. **nima-salamat 저장소에 신규 실험 기능(`blsf-beta` classical lane detector)이 추가**되어 MDPI BLSF 논문과 명칭·파이프라인이 유사하지만, **인용관계는 확인되지 않아 독립 구현 가능성도 배제할 수 없다**(저장소 내 해당 논문 링크 없음). 과거 확정된 논문공장 의심 자료(LineMaster Pro)와 저신뢰 FPS 수치(zbotic.in, fleetstack.io)는 이번 회차도 인용 금지/보류 상태를 유지한다.

### 3.1 Pi5/Bookworm 호환성 — [부분 해소]

- **[미확인/추정]** zbotic.in의 "Pi5 640×480 30+fps" 주장 — 신규 근거 없음, 테스트 방법/환경 불명, 저신뢰 SEO 콘텐츠 평가 유지.

### 3.3 nima-salamat/self-driving-robot — [중요 신규 발견]

[https://github.com/nima-salamat/self-driving-robot](https://github.com/nima-salamat/self-driving-robot)

- **[확인됨]** 최신 10개 커밋 모두 2026-11-02, 전부 CARLA 시뮬레이터 RGB 센서 마운트/카메라 프리뷰 관련 — **실물 Pi 하드웨어 작업 아님.**
- **[확인됨]** README/python/README.md에 `--city-lane-detector blsf-beta` 옵션 존재 — "실험적 classical lane detector, BLSF-style pipeline": weighted grayscale → median-local thresholding → LSD line-segment 검출 → binary line-segment filtering → 열 투영 → sliding window → quadratic RANSAC 피팅. 저장소는 "controlled evaluation 전에는 기본 검출기로 쓰지 말라"고 명시.
- **[확인됨]** ML 기반 차선 모델(unet_depthwise_nano/small)의 구조/데이터 설명 없음, 실측 fps/정확도 전무 — **지난 회차와 동일, 미해소.**
- **[부분확인 — source-verifier]** 저장소의 "BLSF-style pipeline" 명칭·단계가 아래 3.5절 MDPI BLSF 논문과 상당히 유사하나, 저장소에 해당 논문 인용/링크는 전혀 없음. source-verifier 확인 결과: "명칭·파이프라인 유사성은 확인되나 인용관계는 불명 — 독립적 유사 구현 가능성도 배제 못함." **확정적 연관 주장은 금지.**

### 3.4 Pi5 30+fps 미검증 수치 확산 여부 — [변동 없음]

- zbotic.in 주장 신규 근거 없음(원문 접근 실패 지속).
- fleetstack.io — 이번 검색에 재노출 안 됨. **[source-verifier 추가 확인]** fleetstack.io라는 사이트 정체성 자체가 불명확(GPS 플릿관리 SaaS/차량관리 플랫폼 등 혼재 서술), "Pi5 30+fps 차선인식" 주장을 이 사이트가 직접 뒷받침하는 근거를 찾지 못함 — **미확인.**
- **[확인됨, 참고]** [lanefinder](https://awesome.ecosyste.ms/projects/github.com%2Fxadrianzetx%2Flanefinder)(Edge TPU 가속): 카메라 피드 ~30fps, 비디오 재생 ~10fps로 저하. **TPU 가속 결과이므로 Pi5 CPU 단독 성능 근거로 사용 불가.**
- **결론**: 신뢰할 만한 Pi5 전용 벤치마크는 이번 회차도 미등장.

### 3.5 2026년 하반기 신규 기법 (핵심 신규 소스)

- **[부분확인]** MDPI Electronics 15(2), 351 — "Real-Time Deterministic Lane Detection on CPU-Only Embedded Systems via Binary Line Segment Filtering (BLSF)" (Shang-En Tsai, Shih-Ming Yang, Chia-Han Hsieh). URL: https://www.mdpi.com/2079-9292/15/2/351 , preprint: https://www.preprints.org/manuscript/202512.1516 (2025-12 preprint, 2026-01 Electronics 15권 2호 게재, DOI 10.3390/electronics15020351).
  - 핵심 주장: "딥러닝은 CPU 전용 플랫폼에서 과도한 지연" → 고전 기하학 기반 BLSF 파이프라인(IPM → median local thresholding → line-segment 검출 → RANSAC 피팅), 자체 297프레임 데이터셋, CULane/LLAMAS Dazzling Light/Night 서브셋 F1 6~7%p 개선.
  - **[source-verifier 검증]** "2GHz ARM CPU 전용 플랫폼 실시간 유지" 주장은 preprint 맥락에서 확인되나, **"2GHz"가 특정 라즈베리파이 모델 표준 클럭과 일치하지 않음**(Pi4 표준 1.5GHz, Pi5 표준 2.4GHz; 2GHz는 Pi4 오버클럭 수치로만 존재) → "라즈베리파이 특정 모델 매칭"은 **미확인(반증 쪽에 가까움)**, 범용 ARM SBC 또는 오버클럭 조건 가능성.
  - **[source-verifier 검증]** F1 6~7%p 개선 수치는 **2025-12 preprint에서만 확인**, 2026-01 MDPI 최종 출판본에서 동일 수치 유지 여부는 원문 미열람으로 **미확인.**
  - **[source-verifier 발견]** preprint 저자소속(Chang Jung Christian University) vs 검색된 MDPI 페이지 소속 표기(National Cheng Kung University) 간 불일치 발견 — 버전차이/정정 가능성, 추가 확인 필요.
  - 원문(mdpi.com)은 전부 WebFetch 차단으로 미열람, 검색 스니펫 기반.

- **[부분확인]** arXiv 2601.01696 — "Real-Time Lane Detection via Efficient Feature Alignment and Covariance Optimization for Low-Power Embedded Systems" (Yian Liu 외 5인, 제출 2026-01-05). URL: https://arxiv.org/abs/2601.01696.
  - Covariance Distribution Optimization(CDO) 모듈, 추론 연산량 증가 없이 손실항만 추가, CULane/TuSimple/LLAMAS 6개 모델에서 0.01~1.5% 정확도 개선.
  - **[source-verifier 검증]** 0.01~1.5% 수치는 5개 독립 2차 소스(emergentmind.com/papers/2601.01696, themoonlight.io 리뷰, fugumt, catalyzex, deeppaper)에서 일치 확인됨(단 모두 원문의 2차 요약, arXiv 원문 직접열람은 차단되어 미열람).
  - **[source-verifier 검증]** **"Raspberry Pi"를 명시적으로 언급하는 소스는 5개 중 하나도 없음** — "저전력 임베디드=Pi 포함"이라는 가정은 **미확인(사실상 반증에 가까움)**. 0.01~1.5% 개선은 "미미한 수치"라는 맥락이 요약 전반에서 뚜렷함.

- **[부분확인]** arXiv 2604.02188 — "Lightweight Spatiotemporal Highway Lane Detection via 3D-ResNet and PINet with ROI-Aware Attention" (Sorna Shanmuga Raja, Abdelhafid Zenati, City St George's University of London, 제출 2026-04-02). URL: https://arxiv.org/abs/2604.02188.
  - 2D+1D 분리 경량 3D-ResNet + PINet 디코더.
  - **[source-verifier 검증 — 중요]** web-researcher가 제시한 "TuSimple 모델2 93.40% 정확도" 수치를 **독립 2차 검색 2회 모두에서 확인하지 못함**(alphaxiv.org 미러에도 해당 수치 없음). **근거 빈약 — 본 보고서에서는 "미확인/출처 불명"으로 표기하며 수치 자체의 신뢰도를 낮게 처리한다.**
  - 고속도로 환경 타깃, Pi급 저사양 임베디드 타깃 여부 불명확, 하드웨어 플랫폼 미확인.

- **[부분확인]** arXiv 2604.22872 — "Vision-Based Lane Following and Traffic Sign Recognition for Resource-Constrained Autonomous Vehicles" (Md Tanjemul Islam, Md Rafiul Kabir, Central Michigan University, 제출 2026-04-23). URL: https://arxiv.org/abs/2604.22872.
  - 고전 비전 기법 기반 차선추적(조도변화 조건 검증) + 규칙기반 조향, 표지판 인식은 EfficientNet-B0/MobileNetV2.

  - ※ 직전 회차(2026-09-28)에서도 "확인됨"으로 분류한 적 있으나, 이번 회차 재검증 결과 Pi 하드웨어 실측치 미확인 부분이 새로 드러나 등급을 "부분확인"으로 유지한다.

- **[확인됨, 참고]** arXiv 2409.03114 v2(2025-03 개정, 2024년 최초 제출 — **"2026년 신규" 아님 주의**): Beñat Froemming-Aldanondo 외 11인, "Evaluating Low-Resource Lane Following Algorithms for Compute-Constrained Automated Vehicles". URL: https://arxiv.org/html/2409.03114v2 , 코드: https://github.com/benatfroemming/REU-2024-Lane-Following.
  - DBSCAN/K-Means가 가장 견고, 외곽차로 최대 3.5m/s·내곽차로 2.5m/s, 반경 4m 급커브에서 실패율 증가. Donkeycar/Pi 플랫폼 여부 불명.
