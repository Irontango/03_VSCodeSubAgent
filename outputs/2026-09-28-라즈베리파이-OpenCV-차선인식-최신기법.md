- 목적: RC카 프로젝트에 적용할 라즈베리파이 기반 OpenCV 차선 인식 최신 기법의 지속 추적 및 직전 회차 미해결 공백 재검증

## 1. 핵심 요약 (3줄 요약)

1. **직전 회차(2026-08-03)의 두 핵심 공백 — Pi5/Bookworm 호환성, Donkeycar CV 오토파일럿 실전 적용 사례 — 은 이번 회차에도 해소되지 못했다.** 기존 GitHub 프로젝트 4건은 모두 유지보수가 사실상 중단된 상태로 재확인되었고, 포럼성 채널(forum.donkeycar.com, Reddit) 미색인 문제로 Donkeycar 실전 사례는 여전히 미발견이다.
2. **경량 딥러닝 기반 Pi 실전검증 공백을 메울 유력 후보(nima-salamat/self-driving-robot)를 신규 발견**했다. 경량 UNet(Depthwise, 5.2만/25.4만 파라미터) 기반 NCNN 차선검출 모델과 Pi 카메라 벤치마크 스크립트까지 저장소에 존재하나, **실측 fps/정확도 수치는 아직 게시되어 있지 않아 미확인** 상태이며 커밋 이력의 완전한 정상성도 부분확인에 그친다.
3. **미검증 FPS 수치("Pi5 640×480 30+fps") 확산 패턴을 추가로 포착**했다(zbotic.in에 이어 fleetstack.io). 두 도메인 모두 인용 보류 처리하며, 발행일 오탐(자동봇 커밋으로 인한 "가짜 최신" 프로젝트)과 논문공장 의심 신호(LineMaster Pro의 ResearchGate 중복게재)도 새로 확인되어 자료 검증 기준을 한층 강화할 필요가 있다.

## 2. 개요

본 리서치는 직전 회차(2026-08-03)에 이어 라즈베리파이 기반 RC카 프로젝트의 OpenCV 차선 인식 최신 기법을 8주 만에 재조사한 것이다. 직전 회차에서 남긴 4개 이월 항목(Pi5/Bookworm 호환성, Donkeycar 실전 사례, 신규 경량 딥러닝 실측치 탐색, 마케팅성 FPS 수치 확산 여부)을 중심으로 검색을 수행했으며, 신규 학술 자료 3건과 신규 GitHub 프로젝트 1건을 추가로 확보했다. 이번 회차에도 WebFetch 접근 차단(arxiv.org, fleetstack.io, EGRESS_BLOCKED)과 GitHub API 차단(403)이 발생하여 일부 항목은 간접 확인에 의존했다.

## 5. 경량 딥러닝 기반 차선 검출 — 신규 후보 발견

### 5.1 nima-salamat/self-driving-robot (★이번 회차 최대 성과)

[https://github.com/nima-salamat/self-driving-robot](https://github.com/nima-salamat/self-driving-robot)

- **확인됨**: 903 커밋, 8 stars, MIT 라이선스(GitHub 직접 확인). 샘플 확인한 최근 커밋(2026-09-20~09-26, 37건)은 `feat()`/`fix()`/`test()`/`docs()` 컨벤션을 따르는 정상적 커밋으로, 자동생성 신호는 없음.
- **부분확인**: 전체 커밋 이력의 완전한 정상성(기여자 수, 저장소 생성일 등)은 페이지 로딩 실패로 검증하지 못했다. "낮은 인지도(8 stars) 대비 이례적으로 많은 커밋 수(903건)"라는 의심이 완전히 해소되지는 않았으므로 **다음 회차 재검을 권고**한다.
- **확인됨**: PR #11(2026-09-18 병합)에서 경량 UNet 계열 차선검출 모델 2종을 NCNN(.param+.bin) 포맷으로 추가함 — `unet_depthwise_nano`(파라미터 52,191개), `unet_depthwise_small`(파라미터 253,919개, 256×256 입력). `--ml-lane-model` 플래그로 옵트인 방식.
- **확인됨**: `benchmark_lane_models.py --model unet_depthwise_small --camera --camera-mode picam --display --frames 300` 형태의 라즈베리파이 카메라 벤치마크 스크립트가 저장소 내 존재.
- **미확인**: 실측 fps/정확도 수치는 저장소 어디에도 게시되어 있지 않다(벤치마크 스크립트만 존재하고 결과값은 없음). 직전 회차에서 지적한 "경량 딥러닝 Pi 실전검증 사례 부족" 공백을 완전히 메우지는 못했으나, 실측이 가능한 실행 가능 코드베이스를 확보했다는 점에서 유의미한 진전이다.
- 참고: 기존 고전 CV 파이프라인(BEV/IPM 변환 + 가중 그레이스케일 + 지역 임계값 + LSD 기반 "BLSF")도 베타로 병행 존재한다.

## 7. 성능(FPS) 주장 상충 확산 — fleetstack.io (인용 보류)

[fleetstack.io 블로그](https://fleetstack.io/blog/performance-optimization-computer-vision-raspberry-pi-opencv-series)에서 직전 회차 인용금지된 zbotic.in의 "Pi5 640×480 30+fps" 주장과 거의 동일한 문구가 발견되었다. WebFetch가 2회(원 수집 시도 + 재검증 시도) 모두 EGRESS_BLOCKED로 원문 확인이 불가능했다.

- fleetstack 자체는 GPS 차량관제 SaaS 기업 도메인으로 zbotic.in보다 일반 신뢰도는 높음(Scamadviser상 정상 판정).
- 그러나 검색 스니펫에서는 "NEON/VFPv3로 ~30% 속도향상" 등 일반론만 확인되고, "640×480 30+fps"라는 구체 수치의 벤치마크 방법론은 어디서도 확인되지 않았다.
- **판정: zbotic.in과 동일하게 인용 보류 처리.** 동일한 미검증 수치가 여러 도메인으로 확산되고 있는 패턴으로 판단되며, 원문 접근이 재개되기 전까지는 근거로 사용하지 않는다.
- zbotic.in의 두 번째 관련 글(lane-detection-for-self-driving-car-with-opencv-and-pi)도 동일 도메인 신뢰도 문제로 인용 보류 유지.

## 9. Donkeycar 등 기존 프레임워크 — 재확인 결과

- [Donkeycar 공식문서 — Computer Vision Autopilot](https://docs.donkeycar.com/guide/computer_vision/computer_vision/): 직전 회차와 동일한 내용, 변경 없음.
- 공식 문서 외 구체적인 실전 사용자 빌드로그/포럼 사례는 이번 회차에도 미발견.
- YouTube "Donkey car line follower using rospy"는 ROS 기반 별개 구현으로 **추정(미확인)**되며 CV 오토파일럿 문서와는 무관할 가능성이 높다.
- downingbots/RLDonkeycar는 강화학습 기반 프로젝트로 CV 오토파일럿과 무관함을 확인.
- forum.donkeycar.com, Reddit 등 포럼 채널은 WebSearch로 색인되지 않는 것으로 확인되어 미탐색 상태다 — **다음 회차에 별도 검색 전략(예: 사이트 직접 방문, 검색엔진 site: 연산자 재시도) 필요**.

## 10. 방법론/한계

- WebFetch 접근 차단이 이번 회차에는 **EGRESS_BLOCKED** 형태로 재현되었다(arxiv.org, fleetstack.io). 직전 회차 403과는 다른 에러 유형이나 결과적으로 접근 불가라는 점은 동일하다.
- 반면 github.com은 이번 회차 정상 동작했다(직전 회차 403 미재현). api.github.com(GitHub API)은 이번 회차 403으로 신규 차단되어, GitHub 웹페이지 직접 렌더링으로 대체 확인했다.
- forum.donkeycar.com, Reddit 등 포럼성 채널이 WebSearch로 색인되지 않는 경향을 확인했다 — 향후 회차의 방법론 개선 필요 항목으로 기록한다.
- 발행일 오탐 패턴의 신규 변종: "저장소 자체 버전 표기(오래된 연도) vs GitHub 업데이트 메타데이터(최근 날짜)" 불일치가 자동화 봇 커밋 때문일 수 있다는 점을 확인했다. 커밋 메시지 내용까지 직접 확인해야 진짜 활성 프로젝트인지 판별 가능하다.

## 12. 결론 및 다음 회차 이월 항목

1. **전통 CV 파이프라인(Canny+Hough+슬라이딩윈도우)은 8주 전과 동일하게 저사양 Pi(3/3B+)에서 가장 안정적인 실무 선택지**라는 결론에 변함이 없다. 다만 참고 프로젝트들이 모두 유지보수 중단 상태이므로 Pi5/Bookworm 적용 시 직접 검증이 불가피하다.
2. **경량 딥러닝 기반 차선 검출의 Pi 실전검증 공백은 완전히 해소되지 않았으나, nima-salamat/self-driving-robot이라는 실행 가능한 유력 후보를 확보**한 것이 이번 회차의 가장 중요한 진전이다.
3. **마케팅성 FPS 수치("Pi5 30+fps")가 zbotic.in에 이어 fleetstack.io에서도 발견되어 확산 패턴이 의심된다.** 원문 접근이 가능해지기 전까지는 두 출처 모두 설계 근거로 사용하지 말 것을 권고한다.
4. **다음 회차(예정) 이월 항목**:
   - Pi5/Bookworm 호환성 검증 (4개 핵심 프로젝트 모두 유지보수 중단, 대체 자료 탐색 필요)
   - Donkeycar CV 오토파일럿 실전 적용 사례 발굴 (포럼 채널 직접 탐색 전략 수립 필요)
   - **nima-salamat/self-driving-robot 저장소의 실측 fps/정확도 수치 확인** 및 **커밋 이력 전체 정상성(기여자 수, 저장소 생성일) 재검**
   - fleetstack.io 원문 접근 재시도 (EGRESS_BLOCKED 해소 여부 확인)
